# 从 Grok 迁移任务过来：能迁什么、怎么迁

> 一句话结论：**排程定义能迁（半自动），「正在跑的那一次」迁不了。**
> 本文说的是怎么把你 grok.com/tasks 里那些任务搬成这台机器上的定时任务。
>
> **搬 Bot、群、对话历史**（不是任务）走另一条路，见 `docs/grok-bot-migration.md` ——
> 那条路直接读本机 Grok Bot 的客户端库，不用手工抄。

## 1. 先说清楚边界

Grok 那边**没有稳定的任务导出格式**可依赖 —— 官方只在 Tasks 面板里逐条给你看；
X 账户的「下载数据归档」是否包含 Tasks，随版本变，不能当作接口。（我们也不登录你的账号。）

所以这里不做"一键同步"，而是把「**带进来**」这半段做扎实：你给一份清单，它按产品真实的
建任务路径落库。

| 你在 Grok 里有的 | 迁过来会变成 | 能迁吗 |
| --- | --- | --- |
| 任务原话（prompt） | 定时任务的 prompt，字段完全一样 | ✅ 原样 |
| 节奏（每天 / 每周 / 每月 / 每年 + 时间点） | cron（见 §4 映射表） | ✅ 精确映射 |
| 暂停 / 启用状态 | `enabled` / `lifecycle`（暂停的搬过来仍是暂停） | ✅ |
| 任务挂在某个群/项目下 | `room_id`（`--room 群名`） | ✅ |
| 一次正在执行的运行（跑到一半的那次） | — | ❌ 那是进程状态，不是数据 |
| 已经产出的历史结果（那封邮件、那份简报） | — | ❌ 留在 Grok 侧；要留就自己存下来 |
| 通知方式（Grok 用邮件/推送通知你） | 本机是桌面通知 + 交付物落盘 | ⚠️ 不等价，见 §6 |
| Grok 记住的偏好 / 上下文 | — | ❌ 不迁（本机有独立的 Bot 记忆槽） |

## 2. 你需要准备的东西（三种都行，越靠前越准）

1. **清单文本**（最快）：把 grok.com/tasks 里每条任务的「时间 + 原话」逐条抄下来，一行一条。
2. **截图**：把任务列表截图给我，我读图转成清单，再按同样流程跑（读错的地方我会标出来让你核对）。
3. **数据归档 JSON**：X 设置 → 下载数据归档里如果确实带 Grok 任务，把那个 json 给我，
   `--from` 直接吃（脚本会在 JSON 里自己找「像任务数组」的那个数组，不押宝键名）。

清单长这样就行（`#` 开头是注释，`|` 或 Tab 分隔时间与任务）：

```
# grok.com/tasks 上现在跑着的
每天 09:00 | 搜 X 上我关注领域的 24 小时热点，挑 3 条并说明为什么值得看
每周一 10:00 | 汇总上周竞品动态，重点看融资与产品更新
每月 1 日 09:00 | 月度行业趋势简报，控制在 500 字内
每年 1 月 1 日 09:00 | 年度回顾：去年我在 X 上最常讨论的三个话题
0 7 * * 1-5 | 也可以直接给 cron（工作日早上七点把今天的日程发我）
```

## 3. 怎么跑

```bash
# 1) 先预演（默认就是预演，不写任何东西）
node scripts/import_grok_tasks.js --from ~/grok-tasks.txt
#    想挂到某个群下：
node scripts/import_grok_tasks.js --from ~/grok-tasks.txt --room 自媒体内容团队

# 2) 看明白了再真写
node scripts/import_grok_tasks.js --from ~/grok-tasks.txt --room 自媒体内容团队 --apply

# 3) 机器读（给自动化/门禁用）
node scripts/import_grok_tasks.js --from ~/grok-tasks.txt --json
```

预演的输出长这样（三类分开，**看不懂的一条都不写**）：

```
读到 11 条：可建 8 / 已存在 0 / 看不懂 3

会建：
  0 9 * * *    搜 X 上我关注领域的 24 小时热点…
  0 10 * * 1   汇总上周竞品动态…

看不懂，**没有**写入（补上确切时间再跑一次）：
  · [no_time] 每天 | 这条没写时间
  · [no_weekday] 每周 09:00 | 缺星期几
```

三条硬规矩：

- **看不懂就不写**：没有"默认 09:00"这种兜底。猜出来的时间比没建更糟 —— 你以为它在跑，
  其实跑在错的时刻，而且再也不会去看第二眼。
- **走产品路径建**：`executeHostEffects({kind:"routine_schedule"})`，cron 校验、5 分钟间隔下限、
  `next_due` 都交给真实解析器，不在脚本里另写一套。
- **幂等**：同「群 + cron + 同一句话」只留一行；同一份清单跑第二遍只会报"已存在"。

## 4. 节奏映射表（Grok 面板里的四种 + 直给 cron）

| Grok 里的写法 | 本机 cron | 说明 |
| --- | --- | --- |
| 每天 09:00 | `0 9 * * *` | 按本机时区（默认 Asia/Shanghai）解释 |
| 每周一 10:00 / Weekly on Monday at 10:00 | `0 10 * * 1` | 周一到周日 = 1..6,0 |
| 每月 1 日 09:00 / Monthly on the 1st at 09:00 | `0 9 1 * *` | |
| 每年 1 月 1 日 09:00 / Yearly on Jan 1 at 09:00 | `0 9 1 1 *` | |
| 直接给 `0 7 * * 1-5` | 原样 | 5 段 cron 直接收；6 段（带秒）会丢掉秒段并在回执里说明 |

中文数字（七点 / 八点半 / 十点一刻）与英文（8:30am / Tuesday / Mar 3）都认。

## 5. 判据

`node scripts/prove_m53c_grok_task_import.js` → **13/0**

覆盖：13 种时间写法映射；6 种"缺料"各自给出拒绝原因；分类（可建/跳过/看不懂）；
归属解析（名字/ID/找不到/重名）；真写入与 `next_due`；幂等；暂停状态跟着迁。
**三条负向对照**：拆掉"缺时间就拒绝"的守卫 → 「每天」会被造出一个时间；
把「周一」映射成周日 → 周一断言翻假；幂等键去掉 cron → 不同频率的同一句话被判成重复。

## 6. 迁完还要做的一件事：常驻授权

迁过来的是**排程定义**，不是"已经在跑"。本机默认 `BITBOT_ROUTINE_AUTO_EXECUTE` 没开，
到点只会落下待办/草稿，**不会**真的替你去执行 —— 这是产品刻意的设计（自动执行需要用户的
常驻授权，模型没有路径能自己打开它）。

要让它像 Grok 那边一样自己跑，得把这台机器正式武装起来（见 `docs/routine-daemon.md`
与 `scripts/host_routine_daemon.sh`）。脚本每次 `--apply` 后都会把当前状态打印出来，
不会让你误以为它已经在跑。

通知也不等价：Grok 会把结果发邮件/推送给你；本机是桌面通知 + 产物落盘（`data/exports/`、
`data/routines/drafts/`）。要"发到邮箱"，让任务原话里明确写收件人，走的是本机的邮件投递能力。

## 7. 残留（如实）

- **没有界面入口**：目前只有命令行。做一个「导入 Grok 任务」的对话框（选文件 → 预演 →
  逐条勾选 → 写入）是下一步，本轮没做。
- **不做账号直连**：不登录、不代抓。Grok 侧结构一变，脚本只会"更保守地拒绝"，不会猜。
- **X 归档是否含 Tasks 未验证**：我没有你的归档文件，所以 `--from` 对 JSON 只做
  "找像任务数组的那个数组"，命中不了就如实报 `no_task_array`，不硬凑。
