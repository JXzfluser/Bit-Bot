# 信息架构方案：把「一堆功能」变成「四个域」

> 对应设计语言规范 `design-language.md` 的「下一步」第 1、2、3 条。
> 这份是**实施计划**，不是审美建议。每一步都能独立验证。

---

## 一、现状（取证）

从 `hosts/desktop/index.html` 实际读出来的侧栏结构：

```
<aside id="agents">                          ← 主侧栏 280px
  <div id="sidebar-toolbar">                 ← ① 功能入口挤成一排
    [切布局] [搜索] [新对话] [指挥台]
  <div id="sb-search-row">                   ← 搜索展开区
  <div id="vc-sb-indicator">                 ← 语音通话指示
  <details id="sb-bots-rooms">               ← ② 一层塞多件事
    <summary>BitBot</summary>                ←   workspace 名
    <div id="bot-list">                      ←   Bot 列表
    <div class="bot-strip">                  ←   Bot 头像条
    <div class="panel-title">群组</div>
    <div id="room-list">                     ←   群列表
  </details>
  <details class="lab">高级 · 代理 / 队友</details>   ← ③ 工程术语
  ...
</aside>
<aside id="machines">      右侧栏（互斥）
<aside id="conv-rail">     右侧栏（互斥）
<aside id="bot-rail">      右侧栏（互斥）
<aside id="computer-rail"> 右侧栏（互斥）
<aside id="room-rail">     右侧栏（互斥）
```

### 三条病灶

1. **功能入口不归域**
   那一排图标装着四种不同性质的东西：切布局（视图状态）、搜索（查找）、
   创建（动作）、跳指挥台（导航）。用户看到的是「四个按钮」，不是「四个去处」。

2. **一层塞多件事**
   Bot 列表和群列表是**两类对象**，却被塞进同一个 `details`。
   ⇒ 列表栏没有主语 ⇒ 看不清「我现在能操作哪些对象」。

3. **工程术语露给用户**
   「高级 · 代理 / 队友」讲的是内部机制，不是用户心智。
   ⇒ 用户要自己翻译这句话才知道该不该点。

## 二、目标模型（五栏，对齐参考图）

```
┌──────┬──────────────┬─────────────────────────┬──────────────┐
│ 域   │ 对象列表     │ 主区                    │ 上下文栏     │
│ 64px │ 280px        │ 自适应                  │ 340px（可选）│
│      │              │                         │              │
│ 头像 │ 「我的 Bot」  │ 顶栏：标题 + 状态 + 动作 │ 成员         │
│ 对话 │  ─────────   │ ─────────────────────   │  人类 ~ 1    │
│ 指挥 │  Bot 1       │  内容                   │  BOT ~ 1     │
│ 自动 │  Bot 2       │                         │              │
│ 设置 │  ...         │                         │              │
└──────┴──────────────┴─────────────────────────┴──────────────┘
```

**域导航栏（极左 64px）** 解决「一堆功能挤在一起」：
只列**去处**，不列**动作**。

| 域 | 域导航栏上的名字 | 对象列表列什么 | 主区 |
|---|---|---|---|
| 对话 | 对话 | Bot + 群组 | 聊天 |
| 指挥 | 指挥 | 当前团队的成员（+ 其它群提醒） | 指挥台 |
| 自动化 | 自动化 | 定时任务 | 排程列表 |
| 设置 | 设置 | 设置分类 | 设置面板 |

**动作**（搜索、新建、刷新）不占域导航栏的位置：
- 搜索 → 对象列表栏顶部（像参考图那样是列表栏的一部分）
- 新建 → 对象列表栏底部（参考图「+ 创建 Bot」就在底部）
- 刷新 → 主区顶栏

⇒ 域导航栏只回答「我在哪 / 我要去哪」，不回答「我能按哪个钮」。

## 三、迁移路径（每步都能单独验证）

### 第 1 步：加域导航栏，先不搬功能

- 新增 `<nav id="app-rail">`，64px，四项。
- **旧工具栏原样保留** ⇒ 不破坏任何既有行为 ⇒ 门禁全绿。
- 验证：新门 `prove_app_rail.js` 断言四个域都在、且顺序固定。

### 第 2 步：把「指挥台」搬进「指挥」域

- 点「指挥」⇒ 打开指挥台，主区切过去，域高亮。
- 侧栏顶部那排图标里的「指挥台」入口**移除**（它迁到域导航栏了）。
- 验证：`prove_command_panel` 改一条 —— 指挥台入口**只能在域导航栏上**，
  侧栏工具栏里不许再出现第二个入口（门禁要更强，不是换措辞）。

### 第 3 步：对象列表栏按域过滤

- 对话域：Bot + 群组（现在的样子）
- 指挥域：这个群的成员（复用指挥台的成员区数据源，不新建数据源）
- 自动化域：定时任务
- 验证：`prove_app_rail` 追加断言 —— 切域后对象列表栏内容**不一样**。

### 第 4 步：拆侧栏的 `details`

- Bot 列表和群列表分成两段，各自有标题。
- 「高级 · 代理 / 队友」收进设置域，或改名成用户能懂的话。
- 验证：视觉自检（截图）+ 文案审校。

### 第 5 步：右侧栏统一成「上下文栏」

现在 5 个右侧 rail 互斥出现（`body[data-panel]` 切换）⇒ 用户不知道
「为什么有时候右边有东西有时候没有」。
⇒ 统一成一层：对话域显示成员、指挥域显示团队、自动化域显示排程详情。

## 四、这一批的门禁怎么加

新门 `scripts/prove_app_rail.js`：

| 断言 | 内容 |
|---|---|
| AR-1 | 域导航栏存在，且恰好四个域，顺序固定 |
| AR-2 | 每个域都有可见标签（不是只有图标）—— 域是「去处」，用户得知道去哪 |
| AR-3 | 切换域会换主区内容（真点，不是改状态） |
| AR-4 | 同一时刻只有一个域是选中态 |
| AR-5 | 负向对照：把四个域删成一个 ⇒ 必须判红 |

接线：矩阵 + 名册（同批次 13 的 G-146 做法）。

---

## 五、不做什么（避免范围失控）

- ❌ 不改聊天流的交互逻辑
- ❌ 不动那 5 个右侧 rail 的内部实现（第 5 步才动）
- ❌ 不重做配色（本来就干净）
- ❌ 不一次性还完 616 处设计债务（那会改一堆像素，需要单独的基线刷新轮）
