## 0. 为什么会有这份东西

项目的 CSS **本来就有**完整的 scale（`--space-1..9` / `--radius-*` / `--text-*`），
但代码绕过它 —— 实测存量违规 **616 处**：

| 规则 | 处数 | 典型表现 |
|---|---|---|
| R1 行内样式 | 158 | `style="font-size:12px"` 散在 HTML/JS 里 |
| R2 硬编码颜色 | 186 | `#4c8dff`、`#22a06b`、`#f59e0b` 各写各的 |
| R3 硬编码字号 | 10 | 11px / 13px 随手写 |
| R4 硬编码间距 | 203 | `padding: 7px` / `9px` / `20px` —— **不在任何 scale 里** |
| R5 硬编码圆角 | 15 | `border-radius: 9px` / `10px` |
| R6 emoji 当图标 | 44 | 👍 🖼 📷 📎 🎧 |

⇒ 这就是「堆了功能反而看着很丑、很 AI 味」的**根因**：
**名义上有设计系统，实际上每个功能各写各的。**
视觉上找不到节奏（间距没有共同节拍）、找不到层级（组件各自造 token）、
看着像拼接的（emoji 当图标 + 行内样式）。

⇒ ���论：**美观不能靠自觉**。它必须被门禁守住。

## 1. 从参考图提炼的六条设计语言

参考图（人机协作 IM）的克制感来自这六点，不是来自「简洁」两个字：

1. **导航是「域」，不是「功能」**
   极左一条窄图标栏列的是**领域**（创作 / 设计 / 工程），
   不是三十个功能按钮。⇒ 功能入口必须归到某个域下面。

2. **一层只做一件事**
   域导航栏 → 对象列表栏 → 主区 → 上下文栏，四层各司其职。
   ⇒ 不把「Bot 列表 + 群组 + 会话 + 排程」塞进同一栏。

3. **颜色只用来表意**
   黑白灰打底，彩色只出现在两处：**状态**（绿点=在线、红=要你处理）和**强调**。
   ⇒ 灰底 + 细分割线 + 留白 = 90% 的画面。

4. **边框是最后手段**
   参考图里只有输入框和附件卡有 1px 边框。其余靠**背景差**和**留白**分层。
   ⇒ 卡片默认「无边框 + 浅底」，别一上来就描边。

5. **字号就四档**
   标题 16 / 正文 14 / 次要 12 / 极小 11。⇒ 不许出现第五档。

6. **输入区是一个整体**
   一个 pill，左边输入、右边动作。⇒ 不把「输入框 + 两个文字按钮 + 一行提示」
   摊成四件控件 —— 那会让一张卡高一倍。

## 2. 硬规则（门禁自动查）

跑 `node scripts/prove_design_language.js`。

| 规则 | 不许 | 要 |
|---|---|---|
| R1 | 行内 `style="..."`（只允许 CSS 变量赋值、`cursor:pointer`） | 加 class |
| R2 | 硬编码颜色（hex / rgb / hsl） | `var(--token)` |
| R3 | 硬编码字号 | `var(--text-*)` |
| R4 | 硬编码间距（不在 `--space-*` 值域内） | `var(--space-*)` |
| R5 | 硬编码圆角（不在 `--radius-*` 值域内） | `var(--radius-*)` |
| R6 | emoji 当图标 | 内联 SVG（24 视窗、stroke 1.8、无填充） |

**合法值域**（改 scale 时只能加不能减）：

- 间距 `--space-*`：0 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 18 / 24
- 圆角 `--radius-*`：0 / 4 / 6 / 8 / 10 / 12 / 14 / 18 / 22 / 999
- 字号 `--text-*`：10 / 11 / 12 / 13 / 14 / 15 / 16 / 32

### 存量债务怎么办

现有 616 处在 `scripts/design_debt.json` 里，按**指纹**登记
（指纹 = 相对路径｜规则｜归一化内容，**不含行号** ⇒ 改代码不会让台账整体失效）。

- 台账里的**不判红**（存量慢慢还）。
- **新增的判红**：指纹不在台账里，或同指纹出现次数超过台账登记数。
- 还掉一条就从台账里删一条 ⇒ 债务只减不增（ratchet）。

改台账用 `node scripts/prove_design_language.js --refresh-debt`，
但**只在真的还完债时用** —— 它会把当前所有违规重新登记，是还债的终点不是起点。

## 3. 人工检查项（门禁查不了）

这些是「AI 味」里最伤的部分，但没法用正则判定：

1. **一个视图只有一个主语**
   打开任何页面，先问自己：**这屏在讲谁？**（哪个群 / 哪个 Bot / 哪个任务）
   讲不出口 ⇒ 说明信息架构错了，不是样式错了。

2. **功能入口必须归域**
   侧栏顶部那一排图标，装的是**不同性质**的东西（切布局 / 搜索 / 创建 / 跳视图）。
   ⇒ 每加一个入口，先想它属于哪个域。

3. **不给用户看工程术语**
   「高级 · 代理 / 队友」「CM-1906」「devmode」这类是内部词。
   ⇒ 界面文案要说人话。

4. **一屏一个动作**
   一屏里如果有两个同等分量级的「主按钮」，用户就不知道该点哪个。

5. **留白不是浪费**
   参考图 60% 的面积是空的。⇒ 卡片之间宁可多 8px，不要塞进去。

6. **新增功能先问「它替代了什么」**
   加功能而不减东西，界面只会越来越挤。⇒ 新功能上线时，
   至少让一个旧入口消失或降级。

## 4. 排版与间距速查

```
字号   标题 var(--text-title) 14px / 正文 var(--text-base) 15px
       次要 var(--text-sm) 12px / 极小 var(--text-xs) 11px
间距   卡内 var(--space-4) 10px / 卡间 var(--space-5) 12px
       区块间 var(--space-7) 16px / 大段留白 var(--space-9) 24px
圆角   控件 var(--radius-sm) 6px / 卡片 var(--radius-md) 8px
       大卡 var(--radius-lg) 10px / 输入 pill var(--radius-pill) 999px
```
