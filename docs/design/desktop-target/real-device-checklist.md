# 真机验收清单（路线 A · Android 端）

> 用途：让你在真手机上把「能不能连、能不能用」一条条打勾，而不是凭感觉。
> 现状先说清：**当前 APK（`d33184e` 构建）只支持「同一局域网」连接，不支持跨网。**
> 跨网中继（relay）客户端还没接进 Android App（残留 R-A3-3a）——所以「不在同一 Wi-Fi 就连不上」
> 是**产品现状，不是你操作错**。本页把「局域网能测的」和「跨网缺的」分开。

---

## 0. 先做一分钟自测（判断网络通不通）

Mac 当前局域网地址：**`10.201.107.104`**（会随网络变，用 `ipconfig getifaddr en0` 现查）。

1. 桌面 app 里点「账户 → 移动端远程控制 → **允许手机连接**」（必须变成 on）。
2. 手机**连同一个 Wi-Fi**，用手机浏览器打开：
   `http://10.201.107.104:18765/v1/pair/discover`
3. 看到类似下面这段 JSON = 网络通、桌面在接待：

```json
{"ok":true,"service":"bitbot-desktop","name":"<你的电脑名>","version":1,"port":18765,
 "pairing":{"code_active":true,"expires_in_ms":123456}}
```

打不开/超时 = 见下面「§3 连不上先查这 5 条」。

## 1. 局域网连接步骤（当前版本唯一可用路径）

**桌面侧**
1. 打开 Bit Bot 桌面 app（**不能只开终端，也不能让窗口关掉**——服务随 app 生命周期）。
2. 账户菜单 → **移动端远程控制**。
3. 点 **「允许手机连接」** ← 关键。默认入站只绑 `127.0.0.1`（手机连不到），点了才改绑 `0.0.0.0:18765`。
   状态点应从 off 变 on，并显示地址。
4. 点「生成配对码」，得到 6 位数字（有时效倒计时）。
5. macOS 防火墙：系统设置 → 网络 → 防火墙，允许 Electron / node 接收入站连接（或临时关防火墙测试）。

**手机侧**
6. 打开 Bit Bot App（本页交付的 APK）。
7. 让它发现桌面，或输入第 4 步的 6 位码。
8. 成功率 100% 的判据：配对成功 → 进聊天 → 发一句话 → 收到回复。

## 2. 连不上的常见原因（按概率排序）

| 现象 | 真正原因 | 怎么办 |
|---|---|---|
| 手机完全发现不到桌面 | 桌面**没点「允许手机连接」**（入站仍绑 127.0.0.1） | 去点那个按钮，看状态变 on |
| 发现不到 / 连接超时 | 手机和 Mac **不在同一 Wi-Fi/网段**（手机走 5G、或另一个 Wi-Fi） | 连同一个 Wi-Fi；确认都在 `10.201.107.x` |
| 连接超时 | 手机开了 **VPN / Tailscale / 代理**，改写了路由 | 临时关掉手机的 VPN 再连 |
| 连接超时 | 路由器开了 **AP 隔离**（访客网络常见） | 换主网络，或关 AP 隔离 |
| 连接超时 | **macOS 防火墙**挡了入站 18765 | 允许 Electron/node 入站，或临时关防火墙 |
| App 提示「桌面那边还没点『允许手机连接』」 | 桌面 `redeem` 返回 `409 pairing_not_open` | 同上，点按钮 |
| App 提示「配对码不对 / 已失效」 | 码错、过期、或已用过一次 | 桌面重新生成一个 6 位码 |
| 配对成功，但发消息报 401 | 设备公钥没登记上（桌面只认设备签名） | 看 App 的 `deviceTrustNotice`；桌面版本旧就先更新桌面再重新配对 |

### 2.1 本次实测记录（2026-11-03，本机）

查了两处真凭据，结论比"没点按钮"更具体：

| 检查项 | 实测结果 | 说明 |
|---|---|---|
| `data/desktop/pairing.json` | `{"lan_enabled": true, "at": "2026-11-01T15:30:12Z"}` | **开关是开的**，11-01 就点过，不是没点 |
| `lsof -nP -i :18765` | **无输出** | 端口**完全没监听** → 入站服务没起来 |
| `ipconfig getifaddr en0` | `10.201.107.104` | 局域网 IP 正常 |

→ 本次连不上的直接原因：**桌面 app 当前没在跑**（或跑着但入站服务没起）。
`lan_enabled:true` 只决定"起来之后绑 0.0.0.0 还是 127.0.0.1"，**它不会自己把服务拉起来**。
所以第一步不是点按钮，而是**先把 Bit Bot 桌面 app 打开**，再看 `lsof` 有没有监听。

**自测命令（在 Mac 上，验证服务确实在 0.0.0.0 监听）**：

```bash
lsof -nP -i :18765            # 应看到 node/Electron 在 *:18765 或 0.0.0.0:18765
curl -s http://10.201.107.104:18765/v1/pair/discover   # 应回 bitbot-desktop 那段 JSON
```

## 3. 跨网（不在同一 Wi-Fi）—— 当前**不可用**，别浪费时间

- 现状：Android App 里**没有** relay/中转/直连代码（`scanForDesktop` 只扫同 /24 网段、
  `redeemCode` 只 POST 到局域网地址）。中继服务端（A3-1/A3-2）已经做好，但**客户端没接**（R-A3-3a）。
- 结论：手机和 Mac 不在同一局域网时，这个包连不上，是产品缺口，不是你设置错。
- 要跨网能用，需要补一段 Android 代码（relay 客户端：`AUTH/CONNECT/TUNNEL` + 走隧道把 HTTP/SSE
  搬过去 + 「直连/中转」显示），CI 能重打 APK（`android-apk.yml` 已跑通）。

## 4. 局域网通了之后，逐条打勾（R-A2-1 真机验收）

前提：§1 已配对成功、能发消息。以下每条都要「亲眼看到」，看不到就记「不过」，别算通过。

- [ ] **① 进度看得见**：发一条需要工具的消息，十几秒内界面**至少 3 次**进度更新，措辞和桌面一致。
- [ ] **② 锁屏重连**：发消息中途锁屏 30 秒再回来，进度接着出、**不重复**（对应 ON_STOP/ON_START）。
- [ ] **③ 第二轮不串台**：第一轮结束后等 10 秒再发第二条，第二轮**不得**先出现第一轮的行。
- [ ] **④ 多语言**：系统语言切繁体/英文，进度行与回退提示跟着变。
- [ ] **⑤ 回退提示**：在桌面关掉事件双写（或断网）后，手机应显示「回退到整轮模式」的提示，而不是空屏。
- [ ] **⑥ 吊销生效**：桌面「移动端远程控制」花名册里吊销这台手机 → 手机下次请求被拒（≤30 秒）。

任一条不过，就把现象记下来（截图 + 时间），对应修订 `report.md` §8.63 的 R-A2-1/R-A1-4b。

---

## 5. 一句话总结

- **现在能验的**：局域网配对 + 发消息 + 进度（§1、§4）。
- **现在验不了的**：跨网（§3，缺 Android relay 客户端）、真机级进度边界（部分 §4 需你肉眼确认）。
- 连不上时，**先查「允许手机连接」是否点了**（`lsof -i :18765` 有监听才是对的），再查同网段/防火墙/VPN。
